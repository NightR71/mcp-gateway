核心项目

MCP Gateway · 智能体工具网关 开源 · 独立完成

2026.08 开源上线

解决什么问题：工具越来越多时全量塞进模型上下文会导致 token 膨胀与选不准；多个调用方共享工具缺乏隔离与配额；下游 MCP Server 宕机会拖垮整个入口。

  • 四传输统一接入：stdio / SSE / Streamable HTTP / inprocess（进程内加载，适配 Serverless）；新 Server 只在 YAML 声明接入，无需改代码。
  • 语义工具路由：中文 2-gram 分词 + 名称/描述/参数加权打分，按查询只注入 top-k，控制上下文预算；打分器为协议接口，可平滑升级为 embedding。
  • 网关内 Agent 循环：工具路由 → 模型决策 → 网关执行 → 结果回填 → 最终回答；模型可插拔（OpenAI 兼容端点 / 离线模型）。
  • SSE 流式：步骤事件 + 回答逐字流式，事件契约与前端流程图节点一一对应。
  • 安全与多租户：API Key 鉴权、令牌桶限流（分钟桶 + 小时桶）、租户工具白名单（支持前缀通配）、白名单收口到调用点、入参设界、内部错误不透明化。
  • 可靠性：下游断线指数退避自动重连（2s→60s）、调用总超时、按 MCP SDK 错误码分类识别断连与超时。

结果：370+ 项自动化测试（含真实子进程集成测试、停服自愈故障注入测试）+ GitHub Actions CI + Docker 与 Serverless 两套部署形态，均已上线可体验。MIT 开源。

桌面悬浮窗任务 Agent（毕业设计）

2025.08 起持续迭代（2026.03 完成架构重构）

解决什么问题：让语音/文本指令真正驱动桌面与浏览器操作，而不是停在聊天层。

  • Agent 闭环：主循环为「模型 → 工具 → 结果回灌 → 再推理」的递归闭环，带深度上限、失败重试与停止信号检查。
  • 声明式接入开源 MCP：集成开源 Windows-MCP 与 OmniMCP（stdio 声明式配置），自研 Agent 框架统一调度其桌面/浏览器工具，完成跨应用多步流程编排。
  • 传输层抽象与工具管理：三种传输统一分派，跨服务器工具路由，自研 MCP Server 提供上下文工具。
  • 交互与语音：PyQt5 自绘置顶悬浮球 + 全局热键；语音识别接入，前后端以子线程事件循环 + 信号回传桥接。

结果：可演示「语音 → 识别 → Agent 编排 → 桌面元素定位与操作」完整闭环； 代码规模 21 个源码文件 / 约 2,617 行。

归属说明：桌面/浏览器的截图与元素识别能力来自开源 MCP Server 的内置工具， 本人负责 Agent 框架、悬浮窗交互、传输抽象与主循环编排；编码过程为「本人设计 + AI 辅助编码 + 逐文件人工调试」。

鸿蒙智能家居系统 · 本地模型控制闭环

2024.07 – 2025.07（3 人协作：2 人动手开发 + 1 人辅助文档）

解决什么问题：传统智能家居依赖云端、无法用自然语言自主管理，需要本地化、能听懂自然语言并实时监控的控制闭环。

  • 两段式推理 Agent：模型先取实时传感数据拼上下文，再输出控制指令；自定义对话协议同时写入训练模板与推理模板，指令解析失败时兜底不打断对话。
  • 模型微调与本地部署：Unsloth + LoRA 微调 DeepSeek-R1 蒸馏 8B（自建 450+ 条四轮对话数据集，两轮训练分别 250 / 400 条）→ GGUF 量化 → Ollama 本地部署。
  • 后端与数据库：FastAPI + MySQL，6 张核心表 + 触发器，逻辑删除与级联，类型表自关联树形分类；60 秒采集循环 + WebSocket 实时监控。
  • 前端：搭建鸿蒙 ArkTS 主体框架与示例页面，协作同学在其基础上继续开发。

结果：第二十七届中国机器人及人工智能大赛福建赛区三等奖； 形成「设备管理 — AI 交互 — 硬件控制」完整闭环（后端 21 个 RESTful 接口 + WebSocket 实时推送）。
