# 实习一 — 基层医疗公共卫生 SaaS 微服务（随访/数据要素服务）

> 雇主一律行业描述，正文不出现雇主名称；雇主简称仅作**召回别名**保留在 tags（T4 已定 2026-09-14：别名只用于命中，回答一律行业描述）；不写内部表名（正文全部为功能级描述）；归属分级沿用证据文件 D 节。时间：Git 提交窗口 2025-09-03 ~ 2025-11-18（约 2.5 个月；简历写 2025.08 起为入职月，不矛盾）。

## 一句话定位

面向基层医疗机构（社区卫生服务中心/乡镇卫生院）的公共卫生 SaaS 微服务系统，承载居民健康档案、四类慢病随访、网格化管理、健康体检与评估等核心业务；本人以 Java 后端开发身份承担随访服务/数据要素服务的业务模块迭代。

## 痛点

1. 基层随访结果依赖人工逐条录入，存在批量回填的历史数据需要导入链路；
2. 随访变更要跨服务同步档案，跨服务数据链路与字段回填繁琐；
3. 历史代码存在 N+1 查询、幂等缺失等一致性问题。

## 方案（技术形态）

- Java 17 + Spring Cloud 多模块（随访服务、数据要素服务、契约层、第三方对接服务）+ MyBatis-Plus + PostgreSQL + Nacos + OpenFeign + RabbitMQ；多租户（tenantId）+ 院区（hospitalId）双层隔离。
- **Excel 批量导入链路**：键值对竖排解析（Hutool ExcelUtil）+ `@Alias` 声明式表头映射 + 字典缓存中文→码值 → 逐字段校验（白名单/正则/字典翻译/否定语义）→ 全量通过才事务落库 → 错误明细回写与下载。
- 服务间：OpenFeign 跨服务档案回查 + RabbitMQ 异步同步（随访变更 → 档案模块）。

## 个人贡献（19 次提交，全部 Git 可查）

- **A 级（完全新建）**：4 个导入 DTO（覆盖 4 类慢病：高血压/2 型糖尿病/慢阻肺/严重精神障碍，共 165 字段 / 156 个 `@Alias` 映射）+ 导入结果 VO + 字典修正 SQL。
- **B 级（宿主文件中本人新增方法）**：导入总入口与错误文件下载、4 类慢病"校验+事务落库"方法、4 组 DTO→实体转换、字典模糊匹配、地址解析工具方法、按社区统计病种人数的 Mapper 方法等。
- **C 级（修复与增强）**：网格-团队关系幂等修复 + 列表批量回显（N+1 → 批量 IN 查询 + 内存 Map 回填）、家庭档案删除关联清理与事务回滚、体检子表幂等重建（先删后插 + 重置主键）、症状"原文+码值"双写、评估时间范围查询修正（日期精度）、地址层级拆分（小区/楼栋/门牌号，两级正则+兜底）。
- **不冒领边界**：错误明细 Excel 生成方法为接手前既有能力（本人是复用方并新增下载接口）；同事先写的 AI 外呼导入 DTO 不属于本人——不混写。

## 追问预案

### L1（确认层）
- **实习做了什么**：两句话——以 Java 后端身份在 Spring Cloud（Feign/Nacos）微服务团队参与基层公共卫生随访系统迭代；核心是随访数据 Excel 批量导入（4 类慢病、全量校验 + 事务落库 + 错误回执）与跨服务字段回填。
- **导入链路怎么跑**：键值对 Excel → Map → DTO（@Alias 表头映射）→ 逐字段校验 → 全量通过才事务落库 → 错误明细回写下载。
- **团队与协作**：Git 分支协作（自建 2 条需求分支），多轮需求迭代；代码走读 + Git 证据链是可展示方式（内网数据依赖，不运行演示）。

### L2（深挖层）
- **为什么"全量通过才事务落库"**：医疗数据一致性优先——部分失败宁可整批不落、回执指错，也不落半批；错误明细文件让医生可修数重传。
- **N+1 怎么修**：列表页每行查团队 → 批量 IN 查询一次取回 + 内存 Map 回填，2 次查询替代 N+1。
- **幂等怎么修**：网格-团队关系先查后插避免重复关系；体检子表先删后插 + 重置主键保证重导一致。
- **字典匹配为什么模糊匹配**：医生自由文本（"血压偏高/偏高"），字典缓存做包含匹配翻译成码值，翻译结果"原文+码值"双写留痕。
- **跨服务一致性**：随访变更经 RabbitMQ 异步同步档案模块（最终一致），跨服务回查用 OpenFeign。

### L3（挑战层）
- **「数据量大了怎么办？」**（规模诚实，必答）：当前是全量读入 + 单文件单事务，适合基层几十到几百条/次的量级；大文件方案（流式读取、分批提交、失败行回执细化）是"知道怎么改"而非"已实现"——如实说，再讲改法。
- **「地图可视化是你修的吗？」**：简历该句无直接代码证据，**统一改用可证口径**：实现居民地址层级拆分（小区/楼栋/门牌号，两级正则+兜底）并修复网格化统计与数据一致性问题。
- **「团队多大 / 职衔是什么」**：10+ 人 Java 微服务团队（口述级）；职衔按工作内容表述为"AI 方向实习生，主要承担 Java 业务模块开发"。
- **「前端/其他模块是你做的吗」**：归属分级如实——A 级新建文件 Git 可证，B/C 级是宿主文件中的本人方法与修复；不把同事的 AI 外呼 DTO 与既有错误 Excel 能力写进自己成果。
