# 毕业设计 — 基于开源 MCP 的桌面悬浮窗任务 Agent

> 归属分级沿用证据文件 D 节（不重新推断）；时间区间为文件时间戳**推断非事实**。

## 一句话定位

运行在 Windows 桌面的「语音 → LLM → MCP 工具 → 桌面操作」Agent：PyQt5 自绘置顶悬浮球 + 全局热键，语音经百度识别转文字，后端 LLM 决策，经 MCP 协议调用本地/远程工具完成桌面任务，结果回显气泡。

## 痛点

1. 桌面重复操作耗时，想让 LLM 真正"动手"操作桌面，而不是只聊天；
2. 当时开源桌面 MCP Server 对中文指令不友好，中文用户上手门槛高（描述的是当时开源生态的客观局限）。

## 方案

- **Agent 闭环**：主循环 = 「LLM→工具→结果回灌→再推理」递归，深度上限 50；失败重试 3 次 + 重试前重置上下文；停止信号三处检查，手动停止不重试（已知取舍：每轮清历史，禁用多轮记忆）。
- **传输抽象**：stdio / SSE / StreamableHTTP 三种传输统一分派，`shutil.which` 解析 npx/uvx，`AsyncExitStack` 托管连接生命周期；跨服务器工具路由用 O(1) 查表。
- **声明式接入开源 MCP**：三份 JSON 运行配置声明式接入 Windows-MCP 与 OmniMCP（桌面/浏览器操作能力来自它们内置工具）。
- **自研 MCP Server**：2 个文件 4 个工具（桌面 3 + 上下文 1），含"默认使用该工具"的 LLM 引导式描述。
- **前后端线程桥**：子线程常驻事件循环 + `run_coroutine_threadsafe` + `pyqtSignal` 回传 + 单飞阀门。
- **语音链路**：PyAudio（16 kHz/单声道/1024 帧）+ 百度语音识别 REST；LLM 走 OpenAI SDK 兼容端点（DeepSeek）。
- **架构分层**：`main → factory → {config, core, services, session}` 单向依赖，会话层只依赖 `LLMClientProtocol`/`ToolRegistryProtocol`（依赖倒置）；重构设计文档 181 行先行。

## 个人贡献（归属表述红线内）

**我设计并实现了 Agent 核心逻辑与悬浮球交互界面（含语音识别集成），AI 辅助我完成编码，逐文件调试落地。** 开发流程：设计文档先行（早于实现 81 天）→ 本人定框架 → AI 生成 → 人工确认落地 → 分散三轮人工调试——设计先行的 AI 协作流程应当主动讲，是加分项。

## 结果

- 可复述演示场景：「AI 帮我打开 B 站看看人民日报」——语音 → 识别 → Agent 闭环 → 调用开源 MCP 内置的截图与屏幕元素识别工具 → 元素框选 → 执行点击/输入。即**基于开源 MCP 内置截图与元素识别能力 + Agent 闭环编排**，实现语音指令驱动的桌面/浏览器自动化与跨应用多步工作流。
- 活跃源码 21 个 `.py` / **2,617 行**（wc -l 实测；项目证明记 2,618，±1 为行尾换行计数差，两口径均如实保留）。
- 项目无 Git 提交历史（0 commit）——归属靠设计文档、文件时间戳链与内容比对复核（项目证明 §8 给出 8 组 PowerShell 复核命令）。

## 追问预案

### L1（确认层）
- **项目整体怎么工作**：按"语音 → 文字 → Agent → MCP 工具 → 气泡回显"走一遍，点出三传输分派与悬浮窗。
- **用了哪些开源组件**：mcp 官方 SDK、Windows-MCP 与 OmniMCP（声明式接入）、PyQt5、PyAudio + 百度 ASR、OpenAI SDK 兼容端点。
- **为什么用 MCP**：工具接入标准化，三传输一套分发表；这也是后来做 MCP 网关的起点。

### L2（深挖层）
- **Agent 主循环细节**：递归深度上限 50 截断、失败重试 3 次且重试前重置上下文、停止信号三处检查（`chat_session.py:126-204` 可核）。
- **GUI 与 asyncio 怎么共存**：子线程常驻事件循环 + `run_coroutine_threadsafe` 提交协程 + `pyqtSignal` 回传主线程 + 单飞阀门防重复提交。
- **三传输怎么统一**：`mcp_server.py` 分发表 + 三个初始化函数，`shutil.which` 解析可执行文件，`AsyncExitStack` 统一托管。
- **无 Git 怎么证明归属**：设计文档时间早于实现 81 天、目录创建时间按依赖自底向上、两次毫秒级批量写入痕迹、三次分散人工调试时间——8 组复核命令可复现。

### L3（挑战层）
- **「截图识别是自研的吧？」**：纠正归属——截图与屏幕元素识别来自 Windows-MCP/OmniMCP 内置工具，声明式 JSON 接入；自研的是 Agent 主循环对它们的闭环编排（截图回传 → 判定 → 修正/继续）。
- **「中文适配是你实现的？」**：诚实口径——早期曾本地改造过，后来上游补齐了中文支持，改为跟随上游，无代码留存；中文指令由我的 Agent 层直接处理（语音识别 → LLM → 工具编排），桌面执行调用开源工具。
- **已知短板**（主动承认 + 取舍理由）：每轮清历史（无跨轮记忆）、一轮内工具串行、服务器串行初始化无总超时、同名工具静默覆盖、无规范化自动化测试、无依赖清单、音频设备固定 16 kHz 无降级。
- **「每行都是你写的吗 / 用了多少 AI」**：B 级口径——我设计并实现了核心逻辑与界面，AI 辅助编码、我逐文件调试；归属分级（A 设计文档/配置、B 源码、C 集成测试版本、D 第三方）有完整证据链。

## 边界与不作主张（红线，人设必须遵守）

1. 桌面/浏览器操作能力来自第三方开源 MCP Server 的**声明式集成**，不写"自研桌面操作工具"。
2. 自研部分 = Agent 框架、悬浮窗前端、工具管理、传输层抽象、Agent 主循环。
3. 「中文适配」只能作口述经历（曾改过 → 上游补齐 → 跟随上游，无留存），不得表述为"我实现了中文适配"。
4. 截图与元素识别统一表述为「基于开源 MCP 内置能力 + Agent 闭环编排」，不写"自研截图/识别工具"。
5. 不说"全部代码都是我手写的 / 我没用 AI"；不说"JSON 加密 / 用户 ID 鉴权"（无实现）。
6. 成绩类（90 分/优秀/推优/二辩）默认零出现（见红线底稿）；**被专门询问毕设分数**时按 T1 已定固定口径：「一辩 91 分，成功进入学院优秀答辩，最终以学校官方口径为准；项目本身可以完整演示」——此外不给任何分数/排名主张。
7. 演示截图 图片1.jpg 含登录态头像与搜索历史，**仅限本地取证**；任何公开使用前必须遮盖顶栏——AI 不引用该图。
