# 鸿蒙智能家居 APP 系统（hwos）

> 归属分级沿用证据文件 D 节；时间区间 2024-07 ~ 2025-07 为 Git+时间戳**推断非事实**（远端推送止于 2025-02-23，此后成果只在本地）。

## 一句话定位

「鸿蒙 APP + 本地大模型 + 自建后端 + 真实硬件」四位一体的智能家居控制系统——用自然语言（含语音）控制真实电器，而不是 UI 演示。

## 痛点

1. 传统智能家居依赖云端、缺乏 AI 自主管理，要的是本地化、能听懂自然语言并实时监控的闭环；
2. 鸿蒙模拟器无法接入本地 AI——用桌面 AI 演示窗口做工程妥协（这本身是"交付可运行性优先"的取舍证据）。

## 方案

- **后端**：Python 3.11 + FastAPI + uvicorn + PyMySQL；MySQL `schema_home` 6 表 + 1 触发器（逻辑删除 + 级联外键 + 复合唯一索引 + 类型表 `fid`/`level` 自关联树形分类）。
- **两段式推理**：五段式对话协议 `<对话>/<思考>/<响应>/<调用>/<数据>/<控制>` 同时写进训练模板与推理模板；`api_function_mapping` 把 HTTP 路径映射到 Python 函数，模型选中的 API **进程内直调、不走 HTTP 回环**；控制指令解析有兜底（正则不匹配 → 空列表 → 不执行、不打断对话）。
- **模型微调**：Unsloth + LoRA（r=16、alpha=16、7 个投影矩阵）微调 DeepSeek-R1-Distill-Llama-8B（V1；2.0 换 DeepSeek-R1-0528-Qwen3-8B）→ GGUF Q8_0 → Ollama 本地部署。
- **数据集**：自建 450+ 条四轮对话样本（HuggingFace 发布，以本人账号发布可指认；两轮训练分别用 250 / 400 条）；另有 766 行数据集质检脚本（11 个分析函数）。
- **采集与监控**：后台 daemon 线程每 60 秒拉传感器数据写库；WebSocket 实时监控。
- **前端**：HarmonyOS ArkTS/ArkUI，http 单点网关 + Model 字段对齐 + globalState；16 项注册 = 15 个业务页面 + 1 个试验页。

## 个人贡献（归属口径）

3 人协作（2026-09-14 用户裁定）：动手开发 2 人——本人 + 1 位前端同学（本地前后端分离），另 1 位同学辅助编写文档。**本人（A 级，Git 提交可证 + 目录职责 + 结构继承）**：后端全部、数据库 SQL、模型训练与数据集、桌面 AI 演示窗口、前端主体框架与示例页面；前端协作同学在我交付的部分之上继续开发（其增量 Git 无法与代提交的本人代码拆分，属 [待确认]，不冒领也不臆断）。

## 结果

- **第二十七届中国机器人及人工智能大赛 福建赛区三等奖**（2025.06，真实奖项）。
- 形成「设备管理—AI 交互—硬件控制」完整闭环；演示路径：`run_server.py` 启动 → 桌面 AI 窗口说「太热了」→ 日志表新增记录 → 硬件执行。
- 后端 21 个 `.py` / 5,169 行；全项目 85 文件 / 13,395 行（剔除 oh_modules/build/权重，项目证明实测口径）。

## 追问预案

### L1（确认层）
- **项目怎么工作**：自然语言（含语音）→ 本地微调模型 → 两段式推理（先查传感数据拼上下文 → 输出控制指令）→ 进程内直调后端 API → 下发硬件；60 秒采集 + WebSocket 监控。
- **接口与数据规模**：21 个 RESTful 业务路由 + 1 个 WebSocket + 1 个内部推送（`@app.*` 装饰器共 23 处，`main.py` grep 实测）；6 表 + 1 触发器。
- **微调用什么**：Unsloth + LoRA，DeepSeek-R1 蒸馏 8B 基座，GGUF 量化后 Ollama 本地部署。

### L2（深挖层）
- **两段式推理为什么这么设计**：先"查再控"（第一段拿实时传感数据拼上下文），五段式协议写进训练模板让输出结构化可解析；`api_function_mapping` 进程内直调避免 HTTP 回环开销与端口依赖。
- **微调数据怎么来的**：自编四轮对话样本 450+ 条，配 766 行质检脚本（11 个分析函数）管数据质量；两轮训练 250 / 400 条。
- **数据库设计**：逻辑删除 + 级联 + `UNIQUE(userId,name)` + 触发器；类型表 `fid`/`level` 自关联树形分类（设备/空间层级）。
- **LoRA 参数**：r=16、alpha=16、7 个投影矩阵——冻结原权重、旁路低秩矩阵，消费级资源可训。

### L3（挑战层）
- **「微调效果怎么样？」**（诚实口径，必答）：450+ 条自编数据，部分场景输出不稳定，所以工程上做了标签解析兜底保证控制链路可用——这让我理解了小数据微调的边界；**无验证集、无评测指标**，如实承认。
- **「为什么前端提交者不是你？」**（Git 表述纪律）：因网络原因由协作同学代提交，`author` 只证明提交者不证明编写者；前端主体框架与示例页面是我交付的，协作同学在其上继续开发。
- **「仓库里怎么看不到模型部分？」**：最能代表能力的部分（微调、两段式推理、数据集、硬件控制）当时只在本地、从未推送远端——须主动解释，并给代码走读路径。
- **已知缺陷**（追问素材，如实承认）：逻辑删除与 `UNIQUE(userId,name)` 冲突（删除后同名设备无法重建）、空调并发控制无锁无幂等、无连接池、`/api/*` 无鉴权、CORS 全开、冷启动温度基准写死、无单元测试。
