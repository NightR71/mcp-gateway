# 优势证据链 — 主线故事与预设引导顺序

## 主线故事（被问"讲讲你的经历/亮点"）

一句话定位：**我在 MCP 生态里从工具层做到平台层再到基础设施层**。

| 层 | 经历 | 一句话 | 详见 |
|---|---|---|---|
| 工具层 | 毕业设计 | 接入开源 MCP Server、自研 Agent 闭环编排其工具，做桌面智能体 | project-graduation-desktop-agent |
| 平台层 | 鸿蒙智能家居 + 实习二（海洋数据） | 本地模型推理编排、让模型自主调用后端 API（MCP 思想的先导实践）；实习二做 NL2SQL 数据问答（**口述级**） | project-harmonyos-smart-home / project-ocean-nl2sql |
| 基础设施层 | MCP Gateway | 统一接入多 MCP Server 的智能体网关：四传输、语义工具路由、鉴权限流、断线自愈、SSE 流式、全量自动化测试 + CI、线上部署 | project-mcp-gateway |

- 收尾句：「这条线走完，我既能写调用工具的 Agent，也懂 Agent 背后的地基怎么搭。」
- 实务补充：实习期在一段基层医疗信息化 SaaS 微服务团队（行业描述口径，T4 已定）做过真实业务交付，证明 AI 之外的后端工程基本功（事务一致性、幂等、批量导入、N+1 优化）——见 project-internship-medical-saas。

> 措辞纪律：主线故事工具层一句**必须**是「接入开源 MCP Server、自研 Agent 闭环编排」（速答手册旧版"改 MCP Server 支持中文指令"无代码证据，已按证据文件 H9 修正，不沿用）。

## 预设引导顺序（M4 气泡卡顺序，MCP Gateway 三踩坑优先）

预设问题按钮按此顺序排列，点击 = 以面试官身份把问题送进对话流：

1. **「这个网关开发中最难的三个坑是什么？」**（三踩坑，王牌开场）
   ① Vercel 拉不起 MCP 子进程（子进程看不到构建期依赖，工具注册为 0）→ 自研 inprocess 进程内传输，口径：部署环境倒逼架构；
   ② MCP SDK 2.x 断连抛 `MCPError(-32000)` 而非 ConnectionError → 按错误码分类（-32000 断连 / -32001 超时），自愈闭环的最后一公里；
   ③ 语义路由：中文 2-gram 分词 + 名称/描述/参数 3/2/1 加权打分，按查询只注入 top-k 控制 token 预算，Scorer 做成接口可换 embedding。
2. **「语义路由具体怎么实现的？」**（从坑③自然展开；延伸 Scorer Protocol 与 embedding 升级路径）
3. **「断线自愈是怎么做的？」**（指数退避 2s→60s + 错误码分类 + 工具自动重新注册；可加故障注入测试怎么写的）
4. **「微调效果怎么样？」**（鸿蒙诚实口径：450+ 条、部分场景不稳定、标签解析兜底、无验证集——诚实+工程思维是加分点）
5. **「实习里做过最实在的一件事？」**（随访数据批量导入：全量校验 + 事务落库 + 错误回执；19 提交 Git 可查）
6. **「毕设能现场演示吗？」**（可复述场景：语音 → B 站搜索；归属措辞按毕设卡红线）
7. **「NL2SQL 是怎么做的？」**（实习二口述级口径 + 引导到网关 demo_sql 双引擎的已验证实现）
8. 进阶备选（面试官深挖时）：SSE 中间件腰斩流式的坑、错误脱敏收口到 core/ 的坑（README ADR 5/6，M1 新增，均为仓库可验证事实）。

## 面试官质疑应对（压力面）

- **「我觉得你这项目像模板」**：不辩解，给证据链——仓库开源、379 项测试里有真实子进程集成测试和停服自愈的故障注入测试、线上 Demo 可现场点；再讲三个只有实际踩坑才会知道的细节（三踩坑 + ADR 5/6 任选）。
- **「一个人做的可信吗」**：设计文档先行 + 约束文档 + 测试闭环的开发方式（见 evidence-jd-mapping"AI 编程方法论"），归属分级如实（B 级=我设计我调试，AI 辅助编码）。
